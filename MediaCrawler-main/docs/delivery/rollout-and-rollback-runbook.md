# 灰度发布与回滚手册

## 灰度顺序

1. dev：连接 Apollo 和 PostgreSQL，执行两次迁移演练。
2. 启用统一账号写入，保持旧读取，核对旧 API 不再写旧表。
3. 启用统一账号读取，验证发布、互动、风控和统计。
4. 启用统一话术库，验证评论、私信和发布文案。
5. 仅对专用账号启用抖音视频，再启用小红书视频。
6. 真实平台四组场景达到 80% 后进入 staging。
7. 业务签字后才允许扩大灰度；旧 API 和旧表保留一个观察周期。

## 监控

- 迁移成功、冲突和失败数量；
- 可用账号、登录失效、验证码、频控和冷却率；
- 发布成功率、假成功复核数和错误码分布；
- 互动成功率、新旧接口差异、API 5xx 和任务积压。

## 开关回滚

按影响范围从小到大执行：

1. 关闭对应平台视频开关。
2. 关闭统一话术开关。
3. 设置统一账号读取为 false。
4. 必要时设置统一账号写入为 false，并保持旧 API 开启。
5. 每次只变更一个开关并重启/验证 Apollo 加载状态。

## 数据库与代码回滚

- 数据库优先从已验证备份恢复；批次回滚命令见 `migration-runbook.md`。
- 回滚代码前停止调度器和自动任务，记录当前提交和数据库状态。
- 不执行 `git reset --hard`，不删除旧表或统一表。
- 代码回滚后依次验证 OpenAPI、旧账号接口、账号读取和一条非发布业务链路。
