## 2. 总体改动概览

本次更新不是单一页面开发，而是围绕以下四条主线完成业务整合：

1. 将发布账号和互动机器人账号整合为统一账号体系。
2. 将评论、私信和发布文案整合为统一话术体系。
3. 完善跨平台发布结果、错误分类、成功确认、重试和账号风控闭环。
4. 接入 Apollo 运行时配置，移除代码中的敏感硬编码，并提供脱敏状态接口。

前端直接调整的主要页面包括：

- 导航栏与页面路由
- 统一账号管理
- 话术库

通过后端能力间接得到优化的页面包括：

- 获客中心
- 客户线索
- 自动化流水线
- 发布中心
- 互动监控
- 互动量配置
- 私信管理
- 数字人口播
- 数据分析
- 设置及运行配置

## 3. 导航栏和页面路由

### 3.1 更新前

- “账号与互动”分组下提供“机器人账号”入口，路由为 `/bot-accounts`。
- 发布账号由发布模块内部接口单独维护。
- 发布账号和互动账号没有统一页面。
- 旧调用方可能使用 `/publisher-accounts` 或 `/publish/accounts`。

### 3.2 更新后

- “机器人账号”调整为“账号管理”。
- 统一入口改为 `/accounts`。
- `/bot-accounts` 自动跳转到 `/accounts`。
- `/publisher-accounts` 自动跳转到 `/accounts`。
- `/publish/accounts` 自动跳转到 `/accounts`。
- 菜单类型从宽泛的 `any[]` 调整为 Ant Design 标准菜单类型，降低导航数据结构错误风险。

### 3.3 涉及文件

- `MediaCrawler-main/webui-new/src/components/Layout.tsx`
- `MediaCrawler-main/webui-new/src/App.tsx`

## 5. 客户线索页面

- 高意向：80 分及以上
- 中意向：50～79 分

### 5.2 更新后

- 高意向：50 分及以上
- 中意向：25～49 分
- 低意向：25 分以下

### 5.3 涉及功能

以下功能全部同步使用新标准：

- 客户线索列表筛选
- 线索导出
- 地域分布统计
- 批量联系方式采集
- 回复监控任务筛选
- 导出文件中的中文意向等级

### 5.4 优化效果

- 列表、导出、统计和后台自动任务使用同一套等级标准。
- 避免同一条线索在不同功能中显示不同意向等级。
- 扩大高、中意向线索的识别范围。

## 8. 内容运营——发布中心

### 8.1 更新前

- 发布结果主要依赖 `success` 和 `error` 字段。
- 不同平台的返回字段不完全一致。
- 点击发布按钮后存在过早判断成功的风险。
- 登录过期、验证码、限流等错误缺少统一分类。
- 抖音和小红书主要围绕图文发布。

### 8.2 更新后

统一发布结果新增以下字段：

- `task_id`
- `post_id`
- `post_url`
- `error_code`
- `error_message`
- `retryable`
- `started_at`
- `finished_at`

新增标准错误码：

- `AUTH_EXPIRED`
- `CAPTCHA_REQUIRED`
- `RATE_LIMITED`
- `INVALID_MEDIA`
- `CONTENT_REJECTED`
- `UPLOAD_FAILED`
- `SELECTOR_CHANGED`
- `TIMEOUT`
- `UNKNOWN`

### 8.3 发布成功确认流程

发布后不再只依据按钮点击结果，而是依次执行：

1. 检查页面成功提示。
2. 检查发布后的作品 URL。
3. 从 URL 提取作品 ID。
4. 未获得作品链接时，进入作品管理页按标题补偿查询。
5. 未确认成功时不返回发布成功。

### 8.4 账号状态联动

- 登录失效：账号标记为“需要重新登录”。
- 验证码或限流：账号进入冷却。
- 上传失败或超时：允许有限重试。
- 内容违规或素材无效：不进行盲目重试。
- 发布成功：清理失败次数并累计成功次数。

### 8.5 抖音和小红书视频发布

新增能力包括：

- 视频文件上传
- 封面上传
- 视频发布入口选择
- 发布参数设置
- 成功提示确认
- 作品链接和作品 ID 提取

视频发布能力默认关闭，需要分别开启：

```text
DOUYIN_VIDEO_PUBLISH_ENABLED=true
XIAOHONGSHU_VIDEO_PUBLISH_ENABLED=true
```

## 9. 账号与互动——互动监控

### 9.1 更新前

- X/Twitter 批量评论优先使用 AI，失败后读取固定评论模板。
- 评论账号从独立机器人账号池获取。
- 互动账号和发布账号分别维护状态。

- 平台：`x_twitter`

- 互动任务从统一账号池选取账号。
- 按平台、角色、状态、健康度和配额选择账号。
- 评论成功和失败结果回写统一账号状态。

## 10. 账号与互动——统一账号管理

### 10.1 更新前

账号分散在两套体系：

- 发布账号：`publisher_accounts`
- 互动机器人账号：`bot_accounts`

同一个平台账号可能需要重复配置，状态、认证信息、成功次数、失败次数和冷却时间也分别维护。

### 10.2 更新后

新增统一账号表：

```text
unified_accounts
```

新增统一账号接口：

```text
/api/accounts
```

统一账号角色包括：

- `publisher`：发布账号
- `interactor`：互动账号
- `both`：发布和互动共用账号

### 10.3 页面功能

- 按平台筛选
- 按角色筛选
- 按状态筛选
- 按分组筛选
- 分页展示
- 新增账号
- 编辑账号
- JSON 批量导入
- 本地配置校验
- 手动解除冷却
- 逻辑停用账号
- 健康度进度条
- 今日用量和每日配额展示
- 分组和地域展示
- 账号 ID 一键复制

### 10.4 支持平台

- 抖音
- 小红书
- 哔哩哔哩
- 微博
- 知乎
- 快手
- X/Twitter
- 微信公众号
- 微信视频号
- 头条
- TikTok
- Instagram
- YouTube
- Facebook

平台输入同时支持 `dy`、`xhs`、`bili`、`x`、`twitter` 等别名，并在写入前转换为规范平台编码。

### 10.5 账号调度规则

调度时综合考虑：

- 平台
- 发布/互动角色
- 内容能力
- 分组
- 地域
- 优先级
- 健康度
- 冷却时间
- 每日配额
- 最近使用时间

PostgreSQL 环境使用行锁和 `SKIP LOCKED`，避免同一账号被多个并发任务同时选中。

### 10.6 状态和风控规则

- 连续失败达到 3 次后自动冷却。
- 默认冷却时间为 30 分钟。
- 每次失败健康度下降 10 分。
- 成功后清理失败次数。
- 冷却到期后可以重新参与调度。
- 支持手动解除冷却。
- 支持每日配额自动重置。

### 10.7 安全优化

- Cookie/Token 只允许录入或替换。
- 编辑页面不会回显认证原文。
- API 只返回是否配置认证信息及脱敏预览。
- 敏感请求失败时不在浏览器控制台输出请求体。
- 普通用户只能访问自己的账号。
- 管理员可以按归属用户查看账号。
- 删除操作改为逻辑停用，避免误删。

当前“账号校验”仅检查本地认证配置和账号状态，尚未连接目标平台执行远程登录有效性验证。

## 14. 设置和 Apollo 运行配置

### 14.1 更新前

- 配置主要依赖本地 `.env`。
- 部分 Cookie 曾直接写在代码配置中。
- 应用侧无法检查 Apollo 是否成功加载。

### 14.2 更新后

启动配置加载顺序调整为：

1. 加载本地 `.env`。
2. 连接 Apollo Config Service 或 Meta Server。
3. 根据配置决定是否覆盖本地环境变量。
4. Apollo 失败时，根据 `APOLLO_REQUIRED` 决定降级运行或启动失败。

新增受保护状态接口：

```text
GET /api/config/apollo-status
```

接口只返回：

- 是否启用
- 是否加载成功
- App ID
- 环境
- 集群
- Namespace
- 加载配置数量
- 配置来源
- 脱敏错误信息

接口不会返回 Apollo 地址、数据库密码、Cookie 或其他配置值。

代码中的硬编码爬虫 Cookie 已删除，统一改为读取：

```text
CRAWLER_COOKIES
```

## 17. 功能开关和当前默认状态

为避免一次性切换造成业务风险，本次新增以下安全开关：

```text
UNIFIED_ACCOUNT_WRITE_ENABLED=false
UNIFIED_ACCOUNT_READ_ENABLED=false
LEGACY_ACCOUNT_API_ENABLED=true
UNIFIED_SCRIPT_LIBRARY_ENABLED=false
DOUYIN_VIDEO_PUBLISH_ENABLED=false
XIAOHONGSHU_VIDEO_PUBLISH_ENABLED=false
```

### 17.1 默认行为

- 新统一账号页面和 `/api/accounts` 可用。
- 原发布账号和机器人账号 API 继续保留。
- 发布、互动和统计服务仍可读取旧表。
- 统一账号写入默认未启用，避免双写。
- X/Twitter 统一话术调用默认未强制启用。
- 抖音、小红书视频发布默认未启用。

### 17.2 建议上线顺序

1. 执行统一账号迁移 dry-run。
2. 执行迁移 apply。
3. 执行迁移 validate。
4. 开启 `UNIFIED_ACCOUNT_WRITE_ENABLED`。
5. 观察账号新增、状态回写和发布结果。
6. 开启 `UNIFIED_ACCOUNT_READ_ENABLED`。
7. 观察发布、互动、私信和统计数据。
8. 确认旧接口无调用后，关闭 `LEGACY_ACCOUNT_API_ENABLED`。
9. 单独开启统一话术库和视频发布开关。
